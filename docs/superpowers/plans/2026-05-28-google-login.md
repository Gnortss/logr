# Google Login (GSI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add "Continue with Google" sign-in to logr's login page using Google Identity Services (client-side button + redirect POST). Existing accounts whose email matches the Google account are silently linked.

**Architecture:** The login page renders Google's GSI script and button with `ux_mode: "redirect"`. After the user authenticates, Google POSTs an `id_token` (a JWT) to `/auth/google/callback`. The action verifies the token against Google's JWKS using `jose`, then upserts the user with a three-step lookup: (1) by `googleId`, (2) by `email` (silent link — sets `googleId` on the existing row), (3) create new. On success it issues the existing `logr_session` JWT cookie and redirects to `/`.

**Tech Stack:** React Router 7 (framework mode) on Cloudflare Pages, Drizzle ORM + D1 (SQLite), `jose` (already a dep), `bcryptjs` (existing — not used in this flow), GSI client script.

**Note on tests:** The project has no existing test suite (vitest is in devDeps but no config/tests exist). This plan uses manual verification checkpoints rather than introducing a test framework alongside the feature — stay surgical. If you want to add tests later, the pure helpers in `app/lib/auth.google.server.ts` are designed to be testable.

**File structure:**
- New: `app/lib/auth.google.server.ts` — verifies ID token (issuer/audience/JWKS), defines `findOrLinkOrCreateUser`.
- New: `app/routes/auth.google.callback.tsx` — action handler for the GSI POST.
- Modify: `app/db/schema.ts` — make `passwordHash` nullable, add `googleId` unique nullable column.
- Modify: `app/env.d.ts` — add `GOOGLE_CLIENT_ID`.
- Modify: `app/routes/_auth.login.tsx` — loader exposes `GOOGLE_CLIENT_ID`; renders the GSI button above the existing form with an "or" divider.
- Modify: `.dev.vars` (create if missing) — local `GOOGLE_CLIENT_ID`.
- New migration: `db/migrations/0003_google_login.sql` — generated by drizzle-kit.

Routes are auto-discovered by `@react-router/fs-routes` `flatRoutes()` (see `app/routes.ts:4`), so no manual route registration is needed.

## Task 3: Server helper for Google ID token verification + user upsert

**Files:**
- Create: `app/lib/auth.google.server.ts`

- [ ] **Step 1: Create the helper file**

Create `app/lib/auth.google.server.ts` with this exact content:

```ts
import { createRemoteJWKSet, jwtVerify } from "jose";
import { eq } from "drizzle-orm";
import { users } from "~/db/schema";
import type { Database } from "~/lib/db.server";

const GOOGLE_JWKS = createRemoteJWKSet(
  new URL("https://www.googleapis.com/oauth2/v3/certs"),
);

const GOOGLE_ISSUERS = ["https://accounts.google.com", "accounts.google.com"];

export interface GoogleClaims {
  sub: string;
  email: string;
  emailVerified: boolean;
}

export async function verifyGoogleIdToken(
  idToken: string,
  clientId: string,
): Promise<GoogleClaims> {
  const { payload } = await jwtVerify(idToken, GOOGLE_JWKS, {
    issuer: GOOGLE_ISSUERS,
    audience: clientId,
  });
  const sub = payload.sub;
  const email = typeof payload.email === "string" ? payload.email.toLowerCase() : undefined;
  const emailVerified = payload.email_verified === true;
  if (!sub || !email) {
    throw new Error("Google ID token is missing sub or email");
  }
  return { sub, email, emailVerified };
}

export interface ResolvedUser {
  id: number;
  email: string;
}

/**
 * Three-step resolution:
 *  1. Match by googleId → return.
 *  2. Match by email → set googleId on the row (silent link) → return.
 *  3. Otherwise → insert new user (email, googleId, no passwordHash) → return.
 */
export async function findOrLinkOrCreateUser(
  db: Database,
  claims: GoogleClaims,
): Promise<ResolvedUser> {
  const byGoogle = await db
    .select()
    .from(users)
    .where(eq(users.googleId, claims.sub))
    .get();
  if (byGoogle) return { id: byGoogle.id, email: byGoogle.email };

  const byEmail = await db
    .select()
    .from(users)
    .where(eq(users.email, claims.email))
    .get();
  if (byEmail) {
    await db
      .update(users)
      .set({ googleId: claims.sub })
      .where(eq(users.id, byEmail.id))
      .run();
    return { id: byEmail.id, email: byEmail.email };
  }

  const now = new Date().toISOString();
  const inserted = await db
    .insert(users)
    .values({
      email: claims.email,
      passwordHash: null,
      googleId: claims.sub,
      createdAt: now,
    })
    .returning();
  return { id: inserted[0].id, email: inserted[0].email };
}
```

## Task 4: Callback route — handles the GSI POST

**Files:**
- Create: `app/routes/auth.google.callback.tsx`

`@react-router/fs-routes` `flatRoutes()` will auto-register this as `/auth/google/callback`.

- [ ] **Step 1: Create the route**

Create `app/routes/auth.google.callback.tsx`:

```tsx
import type { Route } from "./+types/auth.google.callback";
import { getDb } from "~/lib/db.server";
import { createToken, setSessionCookie } from "~/lib/auth.server";
import {
  verifyGoogleIdToken,
  findOrLinkOrCreateUser,
} from "~/lib/auth.google.server";

const CSRF_COOKIE = "g_csrf_token";

export async function loader() {
  // GSI only POSTs here. Any GET is a stray request.
  return new Response(null, { status: 405 });
}

export async function action({ request, context }: Route.ActionArgs) {
  const form = await request.formData();
  const credential = form.get("credential");
  const csrfBody = form.get(CSRF_COOKIE);

  if (typeof credential !== "string" || typeof csrfBody !== "string") {
    return new Response("Missing fields", { status: 400 });
  }

  const cookieHeader = request.headers.get("Cookie") ?? "";
  const csrfCookie = cookieHeader.match(
    new RegExp(`${CSRF_COOKIE}=([^;]+)`),
  )?.[1];
  if (!csrfCookie || csrfCookie !== csrfBody) {
    return new Response("CSRF check failed", { status: 403 });
  }

  const env = context.cloudflare.env;
  let claims;
  try {
    claims = await verifyGoogleIdToken(credential, env.GOOGLE_CLIENT_ID);
  } catch {
    return new Response("Invalid Google credential", { status: 401 });
  }
  if (!claims.emailVerified) {
    return new Response("Google email not verified", { status: 401 });
  }

  const db = getDb(env.DB);
  const user = await findOrLinkOrCreateUser(db, claims);

  const token = await createToken(
    { userId: user.id, email: user.email },
    env.JWT_SECRET,
  );

  return new Response(null, {
    status: 302,
    headers: {
      Location: "/",
      "Set-Cookie": setSessionCookie(token),
    },
  });
}
```

- [ ] **Step 1: Add a loader (and update the existing one)**

The login route already has a `loader` that redirects logged-in users. Update it to also return the client ID and the absolute callback URL. The callback URL is computed server-side from `request.url` so that the `data-login_uri` attribute is correct in the SSR HTML — GSI's async script may read attributes before React finishes hydration, so the value cannot depend on client-only globals like `window.location`.

Replace `app/routes/_auth.login.tsx` lines 9–20 with:

```tsx
export async function loader({ request, context }: Route.LoaderArgs) {
  const token = getSessionToken(request);
  if (token) {
    try {
      await verifyToken(token, context.cloudflare.env.JWT_SECRET);
      throw new Response(null, { status: 302, headers: { Location: "/" } });
    } catch (e) {
      if (e instanceof Response) throw e;
    }
  }
  const origin = new URL(request.url).origin;
  return {
    googleClientId: context.cloudflare.env.GOOGLE_CLIENT_ID,
    googleLoginUri: `${origin}/auth/google/callback`,
  };
}
```
